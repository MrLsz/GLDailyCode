## 题目描述

给你一个整数数组 `coins`，表示不同面额的硬币；以及一个整数 `amount`，表示总金额。

计算并返回可以凑成总金额所需的**最少硬币个数**。如果没有任何一种硬币组合能组成总金额，返回 `-1`。

你可以认为每种硬币的数量是无限的。

### 示例

```
输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1

输入：coins = [2], amount = 3
输出：-1

输入：coins = [1], amount = 0
输出：0
```

### 约束

- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`

---

## 解题思路

### 核心思想：完全背包求「最少硬币数」

每种硬币可用无限次，这是一个**完全背包**问题；但目标不是求最大价值，而是求**最少硬币个数**，所以用 `min` 而非 `max`。

`dp[j]` 表示凑成金额 `j` 所需的最少硬币数。递推公式：

```
dp[j] = min(dp[j], dp[j - coins[i]] + 1)
```

即：用 `coins[i]` 这枚硬币（`+1`）和不用的两种情况取较小者。

### 初始化（与求最大价值的关键区别）

求最大值时全 0 即可；求**最少**硬币数，必须初始化为「无穷大」：

- `dp[0] = 0`（凑成 0 元需要 0 个硬币）
- 其余 `dp[j] = Integer.MAX_VALUE`（表示暂时无法凑成）

若最终 `dp[amount]` 仍为 `MAX_VALUE`，说明凑不成，返回 `-1`。

### 遍历顺序

完全背包一维写法，硬币可重复使用，因此背包容量**正序遍历**：

```
外层 for 遍历硬币 coins[i]
内层 for 遍历金额 j，从 coins[i] 到 amount（正序）
```

### 复杂度分析

| 维度 | 复杂度 |
|------|--------|
| 时间 | O(n × amount) — n 为硬币种类数 |
| 空间 | O(amount) — 一维 dp 数组 |

## 代码实现

### Java

```java
public class Leetcode_322 {
    public int coinChange(int[] coins, int amount) {
        // dp[j] 表示凑够金额 j 所需的最少硬币数
        int[] dp = new int[amount + 1];

        // 初始化：置为无穷大，表示「无法凑成」
        for (int index = 0; index < dp.length; index++) {
            dp[index] = Integer.MAX_VALUE;
        }
        dp[0] = 0;  // 凑成 0 元需要 0 个硬币

        // 完全背包：正序遍历（每种硬币可用无限次）
        for (int i = 0; i < coins.length; i++) {
            for (int j = coins[i]; j <= amount; j++) {
                // dp[j - coins[i]] 有效时才更新，避免溢出
                if (dp[j - coins[i]] != Integer.MAX_VALUE) {
                    dp[j] = Math.min(dp[j], dp[j - coins[i]] + 1);
                }
            }
        }

        return dp[amount] == Integer.MAX_VALUE ? -1 : dp[amount];
    }
}
```

**写法要点**：
- **初始化无穷大**：求「最少」必须用 `MAX_VALUE` 初始化，不能全 0（否则 min 永远取 0）
- **溢出保护**：`dp[j - coins[i]]` 可能为 `MAX_VALUE`，直接 `+1` 会溢出为负数，必须先判断
- **正序遍历**：硬币可重复用，完全背包标准正序
- **返回值**：`dp[amount]` 仍为 `MAX_VALUE` 说明凑不成，返回 `-1`

---

## 关键点总结

1. **求最少 → 初始化为无穷大 + 递推用 min**，与「求最大价值」的全 0 + max 正好相反
2. **溢出保护**：`MAX_VALUE + 1` 会溢出，必须先判断前驱是否有效
3. **完全背包正序**：硬币无限，金额正序遍历，允许重复使用
4. **不可达返回 -1**：最终仍是 `MAX_VALUE` 即无法凑成
